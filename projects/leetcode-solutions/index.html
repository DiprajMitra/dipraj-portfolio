Overview

A solution that merely passes the judge is often not the solution you want to remember. Without knowing why an approach works — and where it breaks — the pattern does not transfer to the next problem, and the same mistake gets made again under interview pressure.

This repository collects LeetCode solutions where the algorithm is the point. Each submission documents its time and space complexity, explains the reasoning behind the chosen approach, and notes the edge cases where that approach stops being efficient. Writing the same problem in both C++ and Python cross-checks the mental model against two different runtime characteristics.

What it does

  • Optimal or near-optimal approach chosen for each problem, not just a passing one
  • Time and space complexity documented for every solution
  • Edge-case notes explaining when the chosen approach stops working
  • Solutions written in C++ and Python to cross-check two mental models
